## 進め方（第 2 章以降）

1. 残りの章を仮置きのファイル（`N02.ts` などに `export const N02` と `N02_SOURCES`）で作り、`course.ts` に先に登録した（担当が共有のファイルを触らずに済む）
2. 章 2 本ずつを 1 つのサブエージェントに渡した（10 の担当が並行）。渡したのは手順書（`.claude/skills/course-from-prompt/references/chapter-agent-brief.md`）と、章 ID・使う出典・例の画面の目安
3. 担当は自分の章のファイルだけを書き、一次資料を開いて事実を確かめ、合成（`synth`）してカナの読みを全部読み、全場面の静止画を見てから報告した
4. 親（講座全体の担当）は報告を受けた順に、`sources.ts` の note を直し、`syllabus.ts` を `produced` にし、どの講座でも同じ読みにしたい語を `reading.ts` に足し、書き出しを待ち行列で 1 本ずつ流した

## Chalkfile に足したもの

| 足したもの | 理由 |
|---|---|
| `Lecture.material`（教材本文・図・実践課題・要点・参考資料・質問例）と、章 ID・節 ID | 動画だけでなく「読んで学べる教材」と「自分のサービスで試す課題」を持つため。AI チャットが根拠の節を指せるように ID を固定 |
| `Course.syllabus`（全体の目次・到達目標・動画構成）と「準備中」の章の表示 | 先に全体の設計を作り、第 1 章から順に作るため |
| `Course.sources`（出典の一覧・確認日・種類）と `docsOf`・`docsFrom`・`uniqueSources` | 主張ごとに出典 URL と確認日を残すため。章ごとに足した出典を講座の一覧にまとめるため |
| 場面の `evidence`（研究・学術／公式・法令・規格／実務の指針／説明用の仮の例）と `cite` | 研究結果・実務の指針・仮の例を画面でも分けるため |
| 新しい場面 `screens`（架空のアプリの画面を部品で組み、改善前・改善後を並べ、番号つきの注を台詞に合わせて出す） | 「同じ画面の改善前・改善後」を文字でなく図で見せるため（3 講座とも使用） |
| 字幕の焼き込み（`captions`・`CAPTIONS=1 bash scripts/render.sh`） | 音なしでも要点が分かる動画にするため。手元の ffmpeg に字幕の焼き込み（libass）が無かったので Remotion で描く |
| `scripts/build_materials.ts`（Markdown と AI チャット用の `chunks.jsonl`）、`scripts/export_deliverables.ts` | 教材一式と、完成動画・編集用データを章ごとにまとめるため |
| 講座サイトの「教材」「実践課題」「AI に聞く」タブ、講座ごとの言葉（`ui`）、`unitLabel: 'CHAPTER'` | Stripe 講座向けの言葉（「実装に効くメモ」「公式ドキュメント」「LECTURE」）を講座に合わせるため |
| テーマ `paper`、アイコン 40 種 | デザイン講座の見た目と、ナッジ・デザイン・マーケの図に要るアイコン |
| `synth.ts` が `timeline.json` をロックして、自分の章の分だけを書き足す。`Root.tsx` は合成していない章を飛ばす | 担当が同時に合成しても、互いの結果を消さないため。書きかけの章があっても書き出せるように |
| `render.sh` の `CONCURRENCY`（既定 8） | 手元の CPU に合わせて書き出しの並列数を変えるため |
| 画面のモックの入力欄の枠の色 `M.field`（#858E9C、白と 3.31:1） | WCAG 1.4.11（非テキストのコントラスト 3:1）を満たすため（下の 13） |

## つまずいたところ・ダメだったところ

### 第 1 章まで

1. **Node.js 26 で Remotion の Chrome Headless Shell の展開が止まる**: 初めての静止画の書き出しで、ダウンロードの後に 5 分止まった（表示が出ないので、固まったように見える）。pipeline.md の手順で手で展開して解決。README の「作り直す」から辿れなかったので、README に一言足した
2. **npm install の警告**: npm 12 の allowScripts で esbuild のインストール時スクリプトが止められた（esbuild は動いた）。`npm audit` で依存の脆弱性 11 件（Remotion 4.0.440 の下の extract-zip・loader-utils・postcss・ws）
3. **講座の大きさの前提が違う**: Chalkfile は「3〜6 分 × 10〜15 本」の講座を前提にしている。今回は「5〜8 章 × 5〜10 分」。サイト用の動画は `render.sh` の上限（14,500 KiB。コメントでは「15MB 以下」）に収めるために crf を 21 から 2 ずつ上げるが、23 本すべてが crf 27〜29 まで下がった。crf 29 で 1 分あたり約 2.1 MiB なので、上限に収まるのは 6 分 40 秒ほどまで。収まったのは D01・D03・D04 の 3 本だけで、残りの 20 本は crf 29 でも上限を超えた（14.2〜18.0 MiB。暗い背景のマーケ講座は、1 分あたりほかの講座より約 5% 重い）。サイト用の 23 本で約 359 MiB。字幕を焼き込んだ版（crf 20 で固定）は 1 本 22.7〜31.8 MiB
4. **教材・課題・質問例・章 ID の置き場所が無い**: Chalkfile のサイトは「動画・台本・クイズ・公式ドキュメント」だけ。共通プロンプトの 8 つの成果物のうち、教材本文・絵コンテ・実践課題（回答例・評価基準）・AI チャットの質問例・節 ID は、型とサイトと書き出しを足す必要があった
5. **Stripe 講座に寄った部品**: スマホの画面の部品は「サンプルアプリ／Pro プラン」とピンクの色・Stripe の支払いページが固定、アイコンは Stripe 講座で使う分だけ、クイズの「1 / 7」は 7 で固定（バグ。直した）、サイトの言葉も Stripe 向け
6. **場面の項目の意味が分かりにくい**: 時系列の場面（`timeline`）の `sub` は短い札で、長い説明は `detail` に書く決まりだったが、型のコメントに書いていないので、最初は長い文を `sub` に入れて崩れた。数字の場面（`numbers`）は、最初の数字より前に空の枠が出る（直した）
7. **読み間違い**: 「振り返りの」→ふりがえり、「行った」→いった、「前と後」→ぜんご、「使った後」→のち、「表計算」→おもてけいさん、「日本マーケティング協会」→にっぽん。`reading.ts` は全講座で共有なので、足した語が別の講座の読みを変えないか毎回見る必要がある
8. **新しく clone した手元では、サイトの全体を作り直せない**: Stripe 講座の音と動画（13 本）は Git に入っていないので、`build_site.ts` を引数なしで流すと止まる。講座 ID を渡して、作った講座だけを組み立てた（一覧ページの Stripe のカードは画像なし）
9. **出典の URL**: 出版社のサイト（Science・PNAS・OUP・ISO・OECD・NYT）は、スクリプトからの確認では 403 になる（ボット避け）。FTC のダークパターンの報告書は、思っていた URL が 404 だった。規格（ISO）は本文が有料で、定義は公式の閲覧ページで確かめた

### 第 2 章以降

10. **書き出しに時間がかかる**: 1 章（サイト用と字幕の焼き込みの 2 本）で 9〜15 分（動画の長さにほぼ比例）、2 本が重なると 25 分。待ち行列の 20 本（やり直しを含む）で約 4 時間（0 時 10 分〜4 時 9 分）かかり、曜日を直した D04・D07 の書き出し直しに、さらに 23 分かかった。手元ではほかの作業（仮想マシン・iOS シミュレーター）も動いていて、負荷が 100 を超えた。書き出しは待ち行列で 1 本ずつ流すのがいちばん早い
11. **共有のファイルを親が壊した**: 担当の報告を受けて `uiux-engineers/sources.ts` の note を正規表現で直したとき、末尾のカンマが無い項目で、次の項目の頭（`},{ id: 'nng-10-heuristics',`）まで飲み込んだ（TS1117）。その間に合成した担当が一度失敗した。消えた行を戻し、以後は「その項目の中の 1 行だけ」を置き換える道具で直し、直すたびに `tsc` を流した。書き出し済みの章（N04・N05）は、長さが `timeline.json` と一致することで影響が無いと確かめた
12. **待ち行列が別の書き出しと重なった**: 待ち行列は `render.sh` が動いているかだけを見ていたので、別に流していた 2 本続きの書き出しの合間に次を始めた。害は CPU の取り合いだけ。書き出しは 1 つの待ち行列にまとめる
13. **画面のモックの入力欄の枠が、コントラストの基準を満たしていなかった**: 入力欄の枠の色（#C9D0DA）は白と 1.55:1 で、WCAG 1.4.11 の 3:1 に足りない。色とコントラストの章（D05）の担当が、良い例の画面で気づいた。色を教える章の良い例が基準を満たさないのはまずいので、枠を #858E9C（3.31:1）にし、入力欄が出る章（N05・D01・D03・D05・D06・D07・M08）は直した後に書き出した（N05 は直す前に書き出していたのでやり直した）。悪い例（`weak`）の薄い枠はそのまま
14. **例の日付の曜日が違った**: D01 の予約画面の「11 月 8 日（土）」は 2025 年の暦で、2026 年なら日曜日。D03 の担当が、自分の章の例を 2026 年の暦にそろえるときに気づいた。「11 月 7 日（土）」に直して書き出し直した。ところが、書き出した動画から静止画を抜いて見直すと、D04（予約の確認画面）と D07（日時を選ぶ画面）にも同じ「11 月 8 日（土）」が残っていた。見本の第 1 章の例を写した担当の章に、誤りが広がっていた。D04 は「11 月 7 日（土）」、D07 は週を「11 月 7 日（土）〜 13 日（金）」にずらして直し、2 本を書き出し直した。見本を直したら、曜日つきの日付を全章から `grep` で洗い出して、その年の暦で確かめる
15. **同じ出典を 2 つの章で二重に足した**: 担当どうしは互いの追加を見られないので、`w3c-understanding-redundant-entry`（D03・D06）・`waic-wcag22-ja`（D05・D06）・`caa-stealth-marketing-qa`（M04・M06）が、同じ id で note の違う 2 つになった（講座の一覧では先の 1 つだけが残る）。note をまとめて講座の `sources.ts` に移した
16. **公式の文言とほぼ同じ言い回し**: `check_overlap.ts` で、消費者庁の比較広告の考え方・特定商取引法ガイド・WAIC の WCAG 2.2 訳と 16 文字以上続けて同じところが見つかった（教材の文と出典の note で、台詞ではない）。言い換えた。残りの一致は、法律の名前・達成基準の名前（「2.5.8 ターゲットのサイズ (最低限)」など）・WCAG の 4 原則の名前と、「」で分けて出典を言った例文で、固有の名前と引用なのでそのまま
17. **読み間違い（第 2 章以降）**: 「第八章」は「だいはっしょう」と書くと「は」が助詞と読まれてダイワッショオになるので、`s` も漢字のまま。ほかに「深刻度で」→しんこくたびで、「作り手」→つくりしゅ、「描けて」→えがけて、「どうやって作り」→てづくり、「一目で」→イチモクデ、「完成形」→カンセエガタ、「その分」→ソノワケ、「空のまま」→ソラ。全講座で同じ読みにしたい語（振り返り・A/B テスト・表計算・日本・The Mom Test・WCAG・AARRR など）は `reading.ts` に、章だけのものは台詞の `s` に入れた
18. **動画の長さの目安が、計画と手順書で食い違っていた**: `syllabus.ts` の目安は 1 章 7〜10 分（3 講座で計 196 分）、担当への手順書は「5〜7 分を目安」にしていた。仕上がりは 6 分 22 秒〜8 分 26 秒（計 170 分）で、共通プロンプトの 5〜10 分には収まっている。教材の目次（`README.md`）は計画の目安のままだったので、合成した章は実際の長さを出すように `build_materials.ts` を直した

## 読んだページで見つけた AI 宛ての文・隠し文字

どれにも従っていない。出典としては中身だけを使った。

- First Round Review の記事ページの冒頭の「Content Index」: AI ツールに llms.txt を取得してほかのページを探すよう促す案内（マーケ講座の調べもの担当が見つけた。この記事は第 7 章の出典に使っている）
- ISO の委員会のページ（committee.iso.org）のフッターと、OpenStax『Principles of Marketing』のページ: ISO や本の内容を機械学習・生成 AI に使うことを禁じる利用条件。命令ではないが AI 宛ての記述なので報告。ISO は規格の状態と日付の確認だけに使い、OpenStax のページは出典にしていない
- 見えない文字: NN/g のユーザビリティの経験則のページ（例の説明の前のゼロ幅スペース）と、デジタル庁のページ（リンクの文字の中のゼロ幅スペース U+200B が 2 つ）、デジタル庁のガイドブックの PDF（文字にしたときの U+FEFF。組版の区切りと見られる）。読める中身は無く、台本には写していない
- 開けないページ（NYT など）を Web アーカイブ経由で取ろうとした担当の試みは、環境の権限で止められた。担当は迂回せず、二次資料で確かめたうえで、言い切らない書き方にした

## 素材を GitHub に置く（`materials` ブランチ）

- FLAC は可逆で、WAV に戻すと VOICEVOX の出力とバイト単位で同じになる（`pull` が `SHA256SUMS` で確かめる）
- 公開リポジトリなので、素材を main の履歴に入れると clone のたびに付いてくる。gh-pages（動画）と同じく別のブランチに置き、要らない人は `git clone --single-branch` で避けられる

  - `pull`: 45 秒で 1,898 本を取り出し、全部が `SHA256SUMS` と一致

  - `mix`: L12 と D03 の音がバイト単位で同じ
  - `render`: L12 の映像の原版（Remotion の出力）がバイト単位で同じ。Web 用の MP4 は、音が同じで、映像は x264 の再圧縮で細部がわずかに違う（SSIM 0.9997）
