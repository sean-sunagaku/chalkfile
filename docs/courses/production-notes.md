## Chalkfile に足したもの

| 足したもの | 理由 |
|---|---|
| `Lecture.material`（教材本文・図・実践課題・要点・参考資料・質問例）と、章 ID・節 ID | 動画だけでなく「読んで学べる教材」と「自分のサービスで試す課題」を持つため。AI チャットが根拠の節を指せるように ID を固定 |
| `Course.syllabus`（全体の目次・到達目標・動画構成）と「準備中」の章の表示 | 先に全体の設計を作り、第 1 章から順に作るため |
| `Course.sources`（出典の一覧・確認日・種類）と `docsOf` | 主張ごとに出典 URL と確認日を残すため |
| 場面の `evidence`（研究・学術／公式・法令・規格／実務の指針／説明用の仮の例）と `cite` | 研究結果・実務の指針・仮の例を画面でも分けるため |
| 新しい場面 `screens`（架空のアプリの画面を部品で組み、改善前・改善後を並べ、番号つきの注を台詞に合わせて出す） | 「同じ画面の改善前・改善後」を文字でなく図で見せるため（3 講座とも使用） |
| 字幕の焼き込み（`captions`・`CAPTIONS=1 bash scripts/render.sh`） | 音なしでも要点が分かる動画にするため。手元の ffmpeg に字幕の焼き込み（libass）が無かったので Remotion で描く |
| `scripts/build_materials.ts`（Markdown と AI チャット用の `chunks.jsonl`）、`scripts/export_deliverables.ts` | 教材一式と、完成動画・編集用データを章ごとにまとめるため |
| 講座サイトの「教材」「実践課題」「AI に聞く」タブ、講座ごとの言葉（`ui`）、`unitLabel: 'CHAPTER'` | Stripe 講座向けの言葉（「実装に効くメモ」「公式ドキュメント」「LECTURE」）を講座に合わせるため |
| テーマ `paper`、アイコン 40 種 | デザイン講座の見た目と、ナッジ・デザイン・マーケの図に要るアイコン |

## つまずいたところ・ダメだったところ

1. **Node.js 26 で Remotion の Chrome Headless Shell の展開が止まる**: 初めての静止画の書き出しで、ダウンロードの後に 5 分止まった（表示が出ないので、固まったように見える）。pipeline.md の手順で手で展開して解決。README の「作り直す」から辿れなかったので、README に一言足した
2. **npm install の警告**: npm 12 の allowScripts で esbuild のインストール時スクリプトが止められた（esbuild は動いた）。`npm audit` で依存の脆弱性 11 件（Remotion 4.0.440 の下の extract-zip・loader-utils・postcss・ws）
3. **講座の大きさの前提が違う**: Chalkfile は「3〜6 分 × 10〜15 本」の講座を前提にしている。今回は「5〜8 章 × 5〜10 分」。15MB の上限で画質を下げる仕組みが、7 分を超える動画では crf 29 まで下がり、それでも M01 のサイト用は 16MB で上限を超えた
4. **教材・課題・質問例・章 ID の置き場所が無い**: Chalkfile のサイトは「動画・台本・クイズ・公式ドキュメント」だけ。共通プロンプトの 8 つの成果物のうち、教材本文・絵コンテ・実践課題（回答例・評価基準）・AI チャットの質問例・節 ID は、型とサイトと書き出しを足す必要があった
5. **Stripe 講座に寄った部品**: スマホの画面の部品は「サンプルアプリ／Pro プラン」とピンクの色・Stripe の支払いページが固定、アイコンは Stripe 講座で使う分だけ、クイズの「1 / 7」は 7 で固定（バグ。直した）、サイトの言葉も Stripe 向け
6. **場面の項目の意味が分かりにくい**: 時系列の場面（`timeline`）の `sub` は短い札で、長い説明は `detail` に書く決まりだったが、型のコメントに書いていないので、最初は長い文を `sub` に入れて崩れた。数字の場面（`numbers`）は、最初の数字より前に空の枠が出る（直した）
7. **読み間違い**: 「振り返りの」→ふりがえり、「行った」→いった、「前と後」→ぜんご、「使った後」→のち、「表計算」→おもてけいさん、「日本マーケティング協会」→にっぽん。`reading.ts` は全講座で共有なので、足した語が別の講座の読みを変えないか毎回見る必要がある
8. **新しく clone した手元では、サイトの全体を作り直せない**: Stripe 講座の音と動画（13 本）は Git に入っていないので、`build_site.ts` を引数なしで流すと止まる。講座 ID を渡して、作った講座だけを組み立てた（一覧ページの Stripe のカードは画像なし）
9. **出典の URL**: 出版社のサイト（Science・PNAS・OUP・ISO・OECD・NYT）は、スクリプトからの確認では 403 になる（ボット避け）。FTC のダークパターンの報告書は、思っていた URL が 404 だった。規格（ISO）は本文が有料で、定義は公式の閲覧ページで確かめた

## 確かめたこと

- 読み: `.work/kana/<id>.txt` を全部読み、誤読を `reading.ts` と台詞の `s` で直した
- 見た目: 全場面の静止画（場面の終わり）と、字幕つきの版の静止画を見た。スマホの画面のモックの文字が小さすぎたので拡大した
- 長さ: 動画の長さが `timeline.json` と一致（最終版: N01 436.8 秒・D01 395.6 秒・M01 432.3 秒）
- 型: `npx tsc --noEmit`
- 安全: `bun scripts/check_content.ts`（止める 0 件・注意 0 件）
- 事実: 調べもの担当（講座ごとに 1 つ）と事実確認担当（台本だけを渡した別の目、講座ごとに 1 つ）のサブエージェントで、主張と出典を確かめた
- 出典の URL: 全部の URL を開いて確かめた（スクリプトで開けない出版社のページは DOI と Crossref、ブラウザで確認）

## 事実確認で直したこと（主なもの）

| 講座 | 直したこと |
|---|---|
| ナッジ | Mertens ほかの効果量は 2022 年 5 月の訂正後の値（d=0.43、212 本・447 の効果量。訂正前は 0.45）に。Maier ほかは「効果なし」ではなく「補正すると結論が出ない」。DellaVigna & Linos は「小さいがプラス（+1.4 ポイント、対照群比 +8%）、差の約 7 割は出版バイアス」。デフォルトの研究に、再現実験で差が約 11 ポイントに縮んだこと・国の比較で実際の提供数に差がなかったことを足した。DSA 第 25 条の範囲（オンラインプラットフォーム、UCPD・GDPR の対象は除く）。FTC の定義は「スタッフ報告の説明（法律上の定義ではない）」、URL を報告書の PDF に。スラッジは「過剰・不当な手間」で、理由のある手間まで悪いわけではない。良いナッジの条件の「断りやすい」は「できるだけ簡単に（できれば 1 回で）」、300 ポイントは「金銭的インセンティブ寄りで、少額だと定義の境目」、デフォルトは「いちばん強い」ではなく「効果が大きく出やすいと言われる」。良い例の断るボタンは「今はしない」から「受け取らない」に（FTC の報告書は、Not Now で何度も聞き直す手口を挙げている）。悪い例の「多くの人がもうオンに」に、根拠のない社会的証明だという注を足した。『Nudge』のリンクは「No Books Found」の空ページだったので Final Edition のページに替えた |
| UI・UX | ISO 9241-11 の訳語を JIS Z 8521:2020 の「効果・効率・満足」に。定義は言い換えに（逐語訳を避ける）。ヒューリスティクスは「経験則」。「確かめ方は第七章」は誤りで第八章。「1 人でいい」を「2〜3 人に」（1 人だと偶然に引きずられる）。「見た目の答えもほとんど決まる」は言い過ぎなので弱めた。プレースホルダーと、3 つの観点の相関が低い研究を出典に足した。法律で義務になったのは事業者の合理的配慮で、ウェブの改善は努力義務 |
| マーケティング | AMA の定義は「2007 年改訂・2017 年再承認」。日本マーケティング協会の改定は 2024-01-25 で、注で主体に個人を含む。CB Insights は 2014 年版（101 件・42%）と 2021 年版（111 件・35%）を分け、自己申告・複数回答・比較なしの限界を書いた。優良誤認に不実証広告規制を足した。信頼区間は無作為に選んだ前提なので、自分から集まった最初の利用者では不確かさがもっと大きい |

調べもの担当と事実確認担当で、Mertens ほかの訂正前と訂正後の値が逆になっていた（調べもの担当は「訂正後 0.45」、事実確認担当は「訂正後 0.43」）。訂正通知の本文（Europe PMC）を自分で開いて、訂正後が 0.43 だと確かめた。2 つの目で確かめる手順が効いた例で、片方だけを信じていたら逆の数字を載せていた。

調べものの中で 1 つ、AI 宛ての案内文が見つかった（First Round Review の記事ページの冒頭の「Content Index」。llms.txt を取得してほかのページを探すよう促すもの）。従わず、出典としては記事の中身だけを使った。
