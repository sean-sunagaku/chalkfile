# 講座のページの作り直しのお知らせ（2026-11-04・下書き）

これは記録。書いた日のことで、今の手順ではない。今の仕組みは、保存が [保存の設計](../architecture/offline.md)、配り方が [配信の設計](../architecture/delivery.md)、学ぶ人への説明が [学ぶ人向けの説明](../guide/learner-offline.md)。

講座のページの画面（HTML の中の JS）と、保存の画面を作り直す回のお知らせ。全講座のページの版（pageVersion）が変わる。動画とポスターの画像は変わらない。公開する日が決まったら、この文書の日付と、サイトの「新しい版」の案内に出す文（`site/news.ts` の `date`）を、公開する日にそろえる。

## 変わるもの

| もの | 変わること |
|---|---|
| 講座のページの画面 | `site/template.html` の中の JS を TypeScript の役割ごとのファイル（`site/course-page.ts`・`site/page/`）にし、組み立てで 1 本にまとめて、縮めてページに入れる。保存版の HTML が 1 枚で完結するのは前と同じ |
| 学習の記録 | localStorage の形に版の番号 `v` を入れる。鍵と値の形は前と同じなので、前の版のページも読める |
| キーボードと読み上げ | 本文へ飛ぶリンクと `<main>`。タブを ← → と Home・End で移れる。クイズに答えると解説へフォーカスが移る。再生中もカリキュラムのフォーカスが飛ばない。1 文字のショートカットは、動画を選んでいるときだけ効く。保存の進み具合の読み上げは 10% ごと |
| 文字の色 | 薄い文字（時刻・数・注記）を、どの面でもコントラスト比 4.5 以上の濃さにする（サイトだけ。動画の色は変えない） |
| 保存の初めの案内 | 初めて開いたとき、Service Worker が動き出す前に保存状態を問い合わせて「保存機能を準備できません」が残る誤りを直す |
| 無効にした保存版 | 重大な不具合で無効にした版を保存した人には、オンラインで開いたとき、更新して保存する案内だけを出す（合わない「保存版が切り替わりました」を出さない） |
| 「新しい版」の案内 | 何が変わったかを短く出す（文の正本は `site/news.ts`。講座の保存用の教材情報 `offline-manifest.json` の `news` に入る） |

## 学ぶ人に起きること

- 講座を保存した人には、講座を開いて「更新を確認」すると「新しい版があります」が出る。この回の前に保存した版の画面には、何が変わったかの文は出ない（何が変わったかを出す画面は、この回の画面から）
- 「新しい版に更新して保存」を選ぶと、ページとポスターだけを取り直す。動画は、前の保存版から写す（取り直さない）。取り直す量は、講座ごとに 152,814〜935,558 B（全 9 講座で 4,461,691 B）。写す動画は全 9 講座で 879,276,298 B
- 更新するまでは、前の保存版がそのまま使える。オフラインでも再生できる
- ノート・進み具合・クイズの答え・再生の好み（localStorage）は、そのまま読める。新しい画面は、書き直すときに形の版の番号を足す（前の画面も読める形のまま）
- Service Worker を入れた人には、「アプリの更新があります」が 1 回出る（起動用のファイルのうち、一覧のページとオフラインの案内が変わるため。取り直す起動用のファイルは 21 ファイル・733,444 B）
- 保存していない人は、次に開いたときから新しい画面になる（保存の取り直しは起きない）

## 組み立ての前と後

本物の講座を CI と同じ順（素材の取り出し → `synth --cached-only` → `gen` → `build_site --strict`）で組み、この回の前（`5a184e7`）と後の `site/dist` の全 83 ファイルの SHA-256 を比べた。

- 変わったのは 21 ファイル: 全 9 講座の `index.html` と `offline-manifest.json`・一覧のページ（`index.html`）・オフラインの案内（`offline/index.html`）・`sw.js`
- `offline-manifest.json` で変わったのは、ページの項目（大きさと SHA-256）・`pageVersion`・ポスターの URL の `?v=`・`revision`・合計の大きさと、足した `news`。動画の項目（60 本）とポスターの中身は前と同じ
- `sw.js` で変わったのは、起動用のファイルの一覧（一覧のページとオフラインの案内）と、その指紋（`build`）。ほかは、縮めたときの名前の付け方の違いだけで、動きは同じ
- ポスター・一覧のページの画像・アイコン・Web App Manifest・`_headers`・404 のページは、前と同じ
- 講座のページは、1 講座あたり約 10 KB 小さくなった（画面の script を縮めたため。たとえば stripe-billing は 241,056 B から 230,903 B）

## 確かめたこと

- 前の版（`5a184e7` の画面と Service Worker）で本物の講座 ga4-comedy を保存し、新しい版を公開した状態にしてから、前の画面で更新して保存した。取った動画は 0 本・0 B（最初の保存は 6 本・55,561,483 B）。開き直した新しい画面で、前の画面で書いたメモ・クイズの答え・完了の印・再生の速さが、そのまま出た。ブラウザを開き直すと新しい Service Worker になり、前の Service Worker が書いた保存の記録を読み、通信なしで新しい保存版を開いて再生できた
- 前の画面と新しい画面で、全 9 講座・48 本のレクチャーの描いた DOM（操作のあとも）が同じ（作り直しの段階。キーボードと読み上げの直しを入れる前）
- axe: 本物の 9 講座のページの全部のタブと一覧のページ（55 の画面）で、違反の要素が 1,164 件から 0 件。合成の講座の 4 ページで、重大と深刻が 22 件から 0 件
- 保存の進み具合の読み上げ: stripe-billing の保存 1 回で、読み上げの欄に書く回数が 32 回から 13 回（手元の速い通信。遅い通信ほど、前の回数は増える）
- `npm run test:e2e:ci`（32 本）を負荷の高い手元で 3 回続けて流し、3 回とも全部通った。`npm run test:e2e:real`（28 本。公開していない言語の 4 本は skip）では、教材のページだけの更新で取る動画が 0 本・0 B（stripe-billing の 13 本・162,417,300 B を写す）
