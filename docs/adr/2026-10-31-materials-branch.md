# 素材は materials ブランチに置き、履歴を持たない

- 状態: 採用
- 決めた日: 2026-10-31
- 関連: #1（`scripts/materials.ts` を足した）

## 背景

- 台詞の音声（日本語は VOICEVOX、訳の言語は Kokoro の出力）と、BGM・ジングル・効果音は、台本から作る生成物。ただ、作り直すには合成の道具が要り、同じ文でも道具の版で音が変わりうる
- 音声を手元だけに置くと、ほかの人や CI が、同じ動画とサイトを作り直せない
- 音声は大きい。2026-10-31 の記録で、FLAC にして約 385MB、WAV のままだと約 1.1GB あった

## 決めたこと

- 素材（台詞の音声と読み・BGM・ジングル・効果音）は、素材だけを置く `materials` ブランチに置く。main にはマージしない
- ブランチは親の無い 1 コミットにし、push のたびに置き換える。前の版は残さない
- 音声は FLAC（元に戻せる圧縮）で置き、取り出すときに WAV に戻す。`SHA256SUMS` で、戻した WAV が元と同じかを確かめる
- 出し入れは `scripts/materials.ts`（`pull`・`check`・`push`）で行う

## 理由

- main の履歴が音声で太らない。`git clone --single-branch` で main だけを取れば軽い
- 素材があれば、台詞を変えていない章は、合成の道具なしで、時刻・ミックス・動画・サイトまで作り直せる。main の CI もこの形で動く（素材を取り出し、`synth.ts --cached-only` で時刻を決める）
- 同じ WAV からは同じ FLAC ができる。変わっていない台詞は Git の同じオブジェクトになり、push で送り直さない
- 履歴を持つと、使わなくなった台詞の音声も残り続け、ブランチが大きくなる一方になる

## ほかの案

当時の記録とコードから分かる案と、2026-11-02 のリファクタ計画で比べた案:

| 案 | 選ばなかった理由・見直す条件 |
|---|---|
| main に入れる | 履歴が音声で太り続け、clone が重くなる |
| 履歴を持つブランチにする | 使わなくなった音声も残り続ける |
| 講座ごとの変わらない束（tar）を Releases に置き、SHA-256 つきの一覧を main に入れる | main のどのコミットからでも素材を作り直せ、PR どうしもぶつからない。2026-11-02 の計画では、ブランチが 1GB を超えたら移る案にした（T6-03。持ち主が決める） |
| R2 | 配信の仕組みが 1 つ増え、無料の枠を超えると請求される（[Workers Free のままにする](2026-11-02-workers-free-only.md)） |

## 影響

- 前の版の素材は残らない。前の素材が要るときは、そのときの台本のコミットから、合成の道具で作り直す
- 素材は台本のコミットに合わせて作る。`content/` にコミットしていない変更があると、`push` は止まる
- main の CI は素材ブランチから声を取る。新しい台詞の音声は、merge の前に push しておく（足りないと `synth.ts --cached-only` で止まる）
- 今の `push` は、手元の台本にある講座だけで木を作り、ブランチを丸ごと置き換える。ほかのブランチで足した講座の音声は、その講座を含まない台本から push すると消え、元に戻せない
  - そこで、リモートの木に足すだけ（和集合）にする直しを予定している（T0-03）。消すのは、持ち主が明示したときだけにする
- ブランチの大きさ: 2026-11-02 に 8,533 ファイル・約 758MB
