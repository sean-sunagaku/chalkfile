# 動画の古いハッシュを消さない（retained）

- 状態: 採用（期限はこれから付ける）
- 決めた日: 2026-11-02
- 関連: Linear の SUN-1655・SUN-1658。#14（古いハッシュを消さない）・#18（一覧の `retained`）

## 背景

- 公開する動画は、名前に中身の SHA-256 を入れた、変わらないファイルにしている（`L01.<SHA-256>.mp4`）。書き出し直すと、名前の違う新しいファイルになる
- 動画を新しくしたあとも、前の版の動画を指すページが残る
  - 開いたままのタブ。途中へ飛ぶたびに、前の版の動画へ Range の要求を出す
  - サイトを前の版に戻したとき（Workers の rollback）のページ

## 決めたこと

- `scripts/media.ts push` は、Releases にある古いハッシュの動画を消さない。足すだけにする
- 動画の一覧（`site/media-manifest.json`）は、今の動画を `entries` に、前の版の動画を `retained` に並べる
- Worker は `entries` と `retained` の両方を通す。サイトのページが指すのは `entries` だけ

## 理由

- 開いている前のページで、動画の途中へ飛んだときに 404 にしない
- サイトを前の版に戻しても、戻したページが同じ動画を指せる
- Releases は総量と転送量に上限を設けていない（2026-11-02 に確かめた）。古い動画を残しても費用はかからない

## ほかの案

| 案 | 選ばなかった理由 |
|---|---|
| 新しい動画を置いたら、古いハッシュを消す | 開いている前のページと、戻した版のページで、動画が 404 になる |
| 同じ名前で上書きする | 名前で中身が決まらなくなる。保存のときの SHA-256 の照らし合わせと、長いキャッシュ（`immutable`）が使えない。開いている前のページが、途中から別の中身を読む |

## 影響

- Releases に古い動画がたまっていく。1 つの Release に置ける asset は 1000 までで、超える前に `media.ts push` が止まる
- `retained` に期限を付け、期限を過ぎたものを一覧と Releases から片付ける仕組みと手順を足す予定。片付けるときは、`retained` を見てから消す
- 公開の手順の正本は [workers-delivery.md](../workers-delivery.md) の「公開する順番」。言葉の意味は [用語集](../architecture/glossary.md)
