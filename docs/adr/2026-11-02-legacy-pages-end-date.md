# 旧 GitHub Pages の移行コードを 2027-05-02 に終える

- 状態: 提案（持ち主が決める）
- 決めた日: 2026-11-02 に提案
- 関連: Linear の SUN-1658（旧 Pages からの移行）、リファクタ計画の T6-01

## 背景

- 2026-11-02 に、公開先を chalkfile.com に移した（[配信は Cloudflare Workers と GitHub Releases にする](2026-11-02-workers-and-releases.md)）
- 旧サイト（`sean-sunagaku.github.io/chalkfile/`・`gh-pages` ブランチ）は、新しいサイトへの案内だけを出している。旧サイトで講座を保存した人のために、移行用の Service Worker が前の保存版を残し、通信なしでも開けるようにしている
- 保存と学習の記録は、origin が違うので、新しいサイトへ自動では移せない。学ぶ人が、新しいサイトで保存し直す
- main には、移行のためのコードとテストがある
  - `site/legacy-sw.ts`・`scripts/build_migration.ts`・`scripts/deploy_pages.sh`・`site/legacy-config.json`
  - `tests/browser/migration.spec.ts`・`tests/fixtures/legacy-pages/`・`tests/browser-server.ts` の旧サイトの分岐
- これらを、いつ消すかを決める必要がある

## 決めたこと

提案のうちは案。持ち主が決めるまで、ここに従って消す作業はしない。

- 移行のコードを main に置く期限を、新しいサイトの公開から 6 か月後の 2027-05-02 にする
- それまでは、移行のコードを変えない（凍結する）。移行のテストは、公開済みの移行の出力を fixture にして固定する
- 期限の後に、次を 1 本の PR で行う
  - 消す前の commit に tag（`legacy-pages-final`）を打つ
  - 上の移行のコード・テスト・fixture と、文書の節を消す
  - そのあと、訳の動画を別のサイトに置いていた頃の仕組み（保存の検査の `mediaRoots`）を消す
- `gh-pages` ブランチは触らない。静的なページなので、費用 0 のまま動き続ける
- 期限の前に、旧サイトに終わる日を出すかを、持ち主が決める

## 理由

- 旧サイトの利用の数を測っていない。数ではなく、日付で決める
- iOS・iPadOS の Safari は、7 日使わなかったサイトのデータを消すことがある（ホーム画面に追加したアプリは対象外）。旧サイトの保存の多くは、長くは残らない
- 続けて使っている人も、半年あれば新しいサイトに移り終えると見込む
- 期限を決めないと、移行のコード・テスト・fixture を持ち続け、保存の仕組みを直すたびに、旧サイトのことも考えることになる

## ほかの案

| 案 | 選ばなかった理由 |
|---|---|
| 期限を決めずに持ち続ける | 保守の手間が続く |
| すぐに消す | 移り終えていない人が残っているうちに、移行の不具合が見つかっても、直して出し直せなくなる |
| `gh-pages` ブランチも消す | 旧 URL の案内が消え、旧サイトで保存した人が、保存版を開けなくなる |

## 影響

- 期限までは、保存の仕組み（`site/offline-shared.ts` など）を直しても、移行のテストが壊れないようにする
- 持ち主が決めたら、この ADR の状態を「採用」にし、Linear の期日にも入れる。別の日にするなら、日付を直してから採用にする
