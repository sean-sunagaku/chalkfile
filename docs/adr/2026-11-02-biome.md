# lint と format は Biome にする

- 状態: 採用（導入はこれから）
- 決めた日: 2026-11-02（リファクタ計画で道具を比べた）
- 関連: 入れる作業は、これからのリファクタで行う

## 背景

- 決めた日の時点で、コードの lint と format の道具を使っていなかった。長い行が多く、書き方もそろっていなかった
- AI（Claude Code・Codex）と人が並行して書くので、機械で直せる決まりが欲しい
- Remotion の動画は、同じ入力から毎回同じ絵を描く必要がある。`src/` で乱数や今の時刻を使わない決まりを、機械で守りたい
- [CLAUDE.md](../../CLAUDE.md)（いまは [AGENTS.md](../../AGENTS.md)）の「部品に色を直接書かない」も、機械で守りたい

## 決めたこと

- TS・TSX・JS・JSON・CSS の lint と format は Biome にする。設定は `biome.jsonc` 1 つ
- Biome の GritQL のプラグインで、次を止める
  - `src/` での `Math.random()`・`Date.now()`・`new Date()`
  - 部品への色の直書き
- HTML（`site/template.html`・`site/home.html`）は、当面は対象にしない。画面の JS を TS に出したあとで見直す
- 文書（Markdown）は、書式の lint を使わない。リンク・古い言葉・一覧の食い違いは、自前の点検（`check_docs.ts`。予定）で見る

## 理由

- 1 つの道具で lint と format ができ、設定も 1 つで済む。速い
- `biome check --write` を 1 回流せば直せるので、AI も人も同じやり方で直せる
- import の並べ替えも入っている
- GritQL のプラグインで、ESLint を足さずに、このリポジトリの決まりを書ける

## ほかの案

2026-11-02 に比べた案:

| 案 | 選ばなかった理由 |
|---|---|
| ESLint と Prettier | 規則がいちばん多い（型を使う規則や、Remotion の ESLint のプラグインもある）。ただ、道具が 2 つになり、依存と設定が増え、遅い。Remotion の規則がどうしても要るときは、`src/` だけに ESLint を足す |
| oxlint と oxfmt | とても速い。ただ、決めた日の時点で oxfmt は beta で、型を使う lint には TypeScript 7 が要る。TypeScript 7 に上げたあとで、もう一度見る |
| markdownlint（文書） | 書式の規則が、日本語の文に合わない |

## 影響

- 入れるのは、サイトの版を出力から決める直しのあとにする。今のサイトの版は、`scripts/build_site.ts` のソースも含めて決まる。先に整形すると、保存した全員に「新しい版」が出て、取り直しを促してしまう
- 全体の整形は、ほぼ全部のファイルが変わる。開いている講座の PR が 0 の日に、まとめて行う
- 入口は `npm run check`（予定）と、CI の必須チェックにする。git hooks は使わない（[clone した人の手元で勝手に動くものを置かない](2026-10-30-no-auto-run-on-clone.md)）
- Python は ruff、シェルは shellcheck を、別に入れる予定
