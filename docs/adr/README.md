# 決めたことの記録（ADR）

大事な決定を、背景・理由・選ばなかった案と一緒に残す。あとから来た人（AI も）が、今の形になった理由を知り、同じ議論をやり直さずに済むようにする。

## いつ書くか

- 元に戻すのに手間がかかる決定（配信・置き場所・道具・外から指される名前）
- 「なぜこうしないのか」と、あとで聞かれそうな決定
- 持ち主が方針として決めたこと

## ファイル名

`YYYY-MM-DD-<slug>.md`。日付は決めた日、slug は英小文字とハイフンの短い名前（例: `2026-11-02-workers-and-releases.md`）。

- 番号を振らない。並行のブランチで番号がぶつからないようにするため
- 決めた日が分からないときは、記録した日を付け、本文に分かる範囲の時期を書く

## 状態

| 状態 | 意味 |
|---|---|
| 提案 | まだ決めていない。持ち主の判断を待つ |
| 採用 | 決めた。今の形はこれに従う。入れるのがまだのときは「採用（導入はこれから）」と書く |
| 置き換え済み | 新しい ADR に置き換えた。どれに置き換えたかをリンクする |
| 取り下げ | 提案のまま、採らなかった |

## 書き方

- 一度決めたことは書き換えない。変えるときは新しい ADR を書き、古い ADR の状態を「置き換え済み」にして、新しい ADR へのリンクを足す（直してよいのは、状態とリンクの行だけ）
- 手順は書かない。手順の正本へリンクする
- 数字（上限・版・費用）は、決めた日に確かめた値として、日付と一緒に書く。今の値は公式で確かめる
- あとから記録した ADR の「ほかの案」は、当時の記録とコードから分かる範囲で書く。その日に比べたと分かるものは、そう書く
- 文体は [文書の地図](../README.md) の「文書の決まり」に従う

## ひな形

```markdown
# <決めたことを 1 文で>

- 状態: 提案
- 決めた日: YYYY-MM-DD
- 関連: <Linear の番号・PR・文書>

## 背景

何に困っていたか。決めた日に分かっていた事実。

## 決めたこと

## 理由

## ほかの案

| 案 | 選ばなかった理由 |
|---|---|

## 影響

決めたことで変わること・守ること・あとでやること。手順は正本へリンクする。
```
