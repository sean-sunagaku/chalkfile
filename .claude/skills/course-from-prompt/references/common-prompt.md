# 共通プロンプトと、テーマ別の指示

講座を頼むときに渡す文章。共通プロンプトに、テーマ別の指示を 1 つ付けて渡す。下の 3 つのテーマで、実際に `nudge-product`・`uiux-engineers`・`indie-marketing` を作った。

## 共通プロンプト

```text
あなたは、実務に使える学習教材を設計する講師兼動画制作者です。
指定するテーマについて、Webエンジニア・個人開発者が基礎から学び、自分のWebサービスやアプリの改善に使える講座を制作してください。

学習者はソフトウェア開発の経験がありますが、このテーマは初学者です。専門用語を知っている前提にせず、「何か」「なぜ重要か」「どんな場面で使うか」「どう実践するか」の順に説明してください。

【講座の構成】
- 全体を5〜8章程度に分け、各章の学習目標と前提知識を示す。
- 各動画は5〜10分を目安に、1本で扱う中心テーマを絞る。
- 各章は「具体的な困りごと → 考え方 → 良い例・悪い例 → 実践手順 → 演習 → 振り返り」の流れにする。
- Webサービスやアプリの例を使い、学習者が自分のプロダクトに置き換えて考えられるようにする。
- 定義の暗記だけでなく、条件によって使い分ける判断力を身につけられる内容にする。
【各章の成果物】
1. 読んで学べる教材本文
2. ナレーション台本
3. シーンごとの絵コンテ（表示内容・図解・読み上げ・秒数）
4. 図解や比較例
5. 理解確認問題3問と解説
6. 自分のサービスで取り組む実践課題1つと、回答例・評価基準
7. 要点まとめと参考資料
8. 学習画面の右側AIチャットに聞ける質問例3つ
【動画の品質】
- 文章をスライドに並べるだけにせず、図解・比較・具体例を中心にする。
- 画面の文字は要点に絞り、詳しい説明はナレーションと教材本文で補う。
- 日本語字幕を付け、音声なしでも要点を理解できるようにする。
- 動画生成・書き出しが可能な環境なら、完成動画と編集用データも作る。できない場合は、台本・絵コンテまでの完成と明記し、動画を作成済みとは言わない。
【根拠と注意】
- 重要な主張は、一次資料・信頼できる研究・公式資料で確認し、出典URLと確認日を記載する。
- 研究結果、一般的な実務指針、説明用の仮例を区別する。
- 効果を保証せず、限界・例外・失敗例も説明する。
- 他者の教材や記事を丸写しせず、説明と図解は独自に作る。
- 架空の実績・顧客データ・事例を実在するものとして扱わない。
【進め方】
まず全体の目次・到達目標・動画構成を作り、その後、第1章を教材・動画まで一式制作してください。以降の章も同じ形式で展開できるようにしてください。
教材は章・節ごとに整理し、後からAI質問チャットが該当箇所を参照できるよう、安定した章ID・節IDと出典を付けてください。今回の対象は教材・動画制作で、チャット機能の実装は含めません。
```

## テーマ別の指示（例）

### ① ナッジ理論 → `nudge-product`

```text
テーマは「ナッジ理論をプロダクト改善に活かす」です。
選択アーキテクチャ、デフォルト、フレーミング、社会的規範、フィードバック、行動の手間を減らす設計を扱ってください。
ナッジと、強制・金銭的インセンティブ・ダークパターンの違いを明確にしてください。ユーザーの選択の自由と利益を守ることを前提に、オンボーディングや継続利用などの例で説明してください。
最後に「改善したい行動を選ぶ → 障壁を考える → 施策を設計する → 検証指標と悪影響の確認方法を決める」まで実践できる構成にしてください。
```

### ② デザイン → `uiux-engineers`

```text
テーマは「エンジニアのためのUI・UXデザイン」です。
見た目だけでなく、ユーザーの目的、情報設計、操作の流れ、視覚的な優先順位、余白、文字、色、フォーム、エラー表示、アクセシビリティを扱ってください。
同じ画面の改善前・改善後を比較し、「なぜこの変更で分かりやすくなるか」を説明してください。
最後に、自分のサービスの1画面を選び、「問題を見つける → 改善案を作る → 簡単なプロトタイプにする → 利用者に確かめる」まで進められる構成にしてください。
```

### ③ マーケティング → `indie-marketing`

```text
テーマは「個人開発者のためのマーケティング」です。
顧客理解、課題の検証、対象顧客の選び方、ポジショニング、価値の伝え方、価格、集客経路、利用開始・継続までの流れ、効果測定を扱ってください。
広告やSNS投稿だけをマーケティングとせず、「誰の何の課題を、なぜ自分のサービスで解決するのか」から説明してください。
最後に、自分のサービスについて「対象顧客 → 提供価値 → 発信内容 → 集客経路 → 小さな検証計画」を1枚にまとめられる構成にしてください。少ないデータで成果を断定しないことや、売上と利益の違いも説明してください。
```

## Chalkfile での置き場所

| 共通プロンプトの成果物 | Chalkfile の置き場所 |
|---|---|
| 全体の目次・到達目標・動画構成 | `content/<講座>/syllabus.ts`（`docs/courses/<講座>/README.md` に出る） |
| 1 教材本文 | `material.sections`（節 ID つき） |
| 2 ナレーション台本 | `scenes[].lines`（字幕と台本タブにもなる） |
| 3 絵コンテ | `scenes` と合成の時刻から自動（`docs/courses/<講座>/<章 ID>.md`） |
| 4 図解・比較例 | 動画は `screens`・`compare`・`table` など、教材は `material.figures` |
| 5 理解確認問題 3 問 | レクチャーの `quiz` |
| 6 実践課題・回答例・評価基準 | `material.exercise` |
| 7 要点まとめと参考資料 | `material.summary`・`material.references`・`docs` |
| 8 AI チャットの質問例 3 つ | `material.askExamples`（根拠の節 ID つき） |
| 日本語字幕 | サイトは動画の下の帯、`CAPTIONS=1` で焼き込みの版、`export_deliverables.ts` で VTT・SRT |
| 出典 URL と確認日 | `content/<講座>/sources.ts`（`checked`）と、章ごとの `<ID>_SOURCES` |
| 研究・実務・仮の例の区別 | 場面と節の `evidence` |
| 安定した章 ID・節 ID | `nudge-01`・`nudge-01-s03` の形。`chunks.jsonl` に出る |
