# つまずいたところと直し方

3 講座を作ったとき（2026-10）に実際に起きたこと。詳しい経緯は `docs/courses/production-notes.md`。

## 手元の準備

- **Node.js 26 で Remotion の Chrome Headless Shell の展開が止まる**（ダウンロードの後、何も出ずに数分止まる）。手で展開する:

  ```bash
  cd node_modules/.remotion/chrome-headless-shell
  rm -rf mac-arm64 && mkdir mac-arm64 && unzip -q chrome-headless-shell-mac-arm64.zip -d mac-arm64
  printf '144.0.7559.20' > VERSION
  ```

- npm 12 の allowScripts で esbuild のインストール時スクリプトが止められる警告が出る（esbuild は動く）
- 新しい clone には Stripe 講座の音と動画が無いので、`build_site.ts` を引数なしで流すと止まる。作った講座の ID を渡す
- 手元の ffmpeg に字幕の焼き込み（libass）が無いことがある。字幕は Remotion で描く（`CAPTIONS=1`）

## 台本

- **読み**: 「振り返りの → ふりがえり」「行った → いった」「前と後 → ぜんご」「使った後 → のち」「表計算 → おもてけいさん」「日本 → にっぽん」。`reading.ts` は全講座で共有なので、章ごとの直しは台詞の `s` で、どの講座でも同じ読みにしたい語だけを `reading.ts` に入れる
- `timeline` の `sub` は短い札（長い文は `detail`）。長い文を `sub` に入れると崩れる
- 数字の場面は、最初の数字を言う台詞で枠ごと出る。仮の数字は `footnote` に「仮」と書く
- スマホの画面のモックは中身を拡大しないと文字が小さい（`screens` はスマホで 1.3 倍、部品の少ないブラウザは `zoom: 1.5`）
- `phone` の場面は Stripe 講座向けのピンクの部品。ほかの講座は `screens` を使う
- 7 分を超えると、サイト用の 15MB の上限で画質（crf）が 29 まで下がり、それでも少し超えることがある

## 事実

- 調べもの担当と事実確認担当で、同じ論文の訂正前後の値が逆になったことがある（Mertens ほか 2022: 訂正後が d=0.43）。食い違ったら一次資料（訂正通知など）を自分で開いて決める
- 出版社・ISO・OECD・FTC・NYT・日本マーケティング協会のページは、スクリプトや WebFetch では 403 になる。DOI と Crossref、Europe PMC、公式の写し、ブラウザで確かめ、開けなかったことを `note` に書く
- 本のページのリンクが「No Books Found」の空ページだったことがある。URL が 200 を返しても中身を見る
- 言い過ぎの典型: 「いちばん強い」「1 回の操作で」「（少額でも）ナッジではない」「見た目の答えもほとんど決まる」「定義の要約」（実は全文の訳）。事実確認担当にここを見てもらう
- 定義は規格（ISO 9241-11 の訳語は JIS Z 8521:2020 の「効果・効率・満足」）や団体の改定（AMA は 2007 年採択・2017 年見直し、2026 年に見直しを検討中）で変わる。時点を書く

## 並行で作るとき

- 担当には自分の章のファイルだけを書かせる。共有のファイル（`course.ts`・`sources.ts`・`reading.ts`・`timeline.json` を手で）を触らせない。仮置きのファイルを先に登録しておく
- `synth.ts` は `timeline.json` をロックして書く。`Root.tsx` は合成していないレクチャーを飛ばす（書きかけの章があっても書き出せる）
- 動画の書き出しは親が 1 本ずつ流す（1 本の両方の版で 8〜10 分。並べると CPU を取り合う）
